## 〇、全局机制

### 0.1 模块通信

各模块通过 `window.DQF*` 命名空间解耦，互不直接依赖：

```
window.DQF          公共工具 + 精度数据（app.js 提供）
window.DQFCards     五大基线卡片
window.DQFFlow      D3 流程图
window.DQFAnalyzer  讨论诊断器
window.DQFRadar     D3 雷达图
window.DQFCases     案例分析
window.DQFChecklist 自检清单
```

`app.js` 在 `DOMContentLoaded` 时按固定顺序调用各模块的 `init()`。
子模块在脚本解析阶段**只注册对象、不执行逻辑**。

### 0.2 导航

| 行为 | 触发 | 效果 |
|------|------|------|
| 吸顶描边 | `scrollY > 8` | 导航底部出现 `--border` 分隔线 |
| Scrollspy | 滚动 | 当前视口内最靠上的分区对应链接高亮为 `--accent` |
| 锚点跳转 | 点击导航项 | 平滑滚动，`scroll-padding-top` 预留导航高度 |
| 回到顶部 | `scrollY > 620` | 右下角按钮淡入；点击平滑滚回顶部 |

### 0.3 主题

```
初始化：localStorage['dqf-theme'] → 系统 prefers-color-scheme → dark
点击切换按钮 → 反转 dark/light → 写回 localStorage
```

切换后 SVG 图标在月亮 / 太阳之间切换。

### 0.4 滚动 Reveal

带 `.rv` 的元素由 `IntersectionObserver` 监听，进入视口（阈值 0.12，底部内缩 8%）时加 `.is-in`。
命中后 `unobserve`，不重复触发。

带 `.rv-stagger` 的容器，其子元素按 `:nth-child` 获得 40ms 递增延迟。

## 一、Hero

### 1.1 粒子背景

- Canvas 铺满 Hero，DPR 上限 2
- 粒子数自适应：`clamp(26, 面积/22000, 64)`
- 每帧移动，边界反弹，速度 ≤ 0.16px/帧
- 距离 < 118px 的粒子间绘制连线，透明度随距离线性衰减
- 滚动出视口时暂停绘制（`IntersectionObserver` + 空转 rAF）
- `prefers-reduced-motion` 或 Canvas 不可用时完全不启动

### 1.2 五段链路

`Concept → Standard → Evidence → Logic → Cognitive Gain`

- 每段之间的虚线连线上有一个流动光点（`travel` 动画，2.8s）
- 逐段延迟：第 n 段延迟 `(n-1) × 0.35s`
- 悬停单个节点：背景下沉 + 右移 3px

## 二、框架总览 `#overview`

**状态**：`current: 0..7`，默认 1（概念定义）

| 操作 | 效果 |
|------|------|
| 点击任一节点 | 该节点加 `.is-on`（橙色底 + 橙色描边），右侧面板切换为该节点详情 |
| 面板内容 | 中文名 + 英文名 chip → 要回答的问题 → 说明 → 「失败后果」→「怎么修」 |

初始渲染时自动选中第 2 个节点（概念定义），避免首屏空白。

## 三、五大基线卡片 `#baselines`

**状态**：每张卡片独立的 `open: boolean`（初始全收起）

| 操作 | 效果 |
|------|------|
| 点击卡片头 | 切换展开：`.is-open` → 隐藏 teaser、显示 `.card__body`；caret 旋转 180° |
| 展开态描边 | 变为该基线的专属色 `--card-color` |
| 展开动画 | `.card__body` 淡入上浮 0.34s |

**展开内容**：作用 → 为什么重要 → 常见错误 → 示例 chips → 底部「当前要求」条。

**与精度滑块联动**：底部要求条右侧的星级随当前档位实时更新（`setPrecision`）。
例如从「闲聊」拖到「学术研究」，概念定义要求从 ★★ 变为 ★★★★★。

## 四、讨论流程（D3）`#flow`

### 4.1 图形结构

```
        ┌─ 概念一致？ ──NO──→ 回到概念定义
        ↓ YES
        ├─ 标准一致？ ──NO──→ 协商评价标准
        ↓ YES
        ├─ 事实一致？ ──NO──→ 补充可验证证据
        ↓ YES
        ├─ 逻辑成立？ ──NO──→ 修正推理链条
        ↓ YES
        └─ 产生认知？ ──NO──→ 退出讨论
             ↓ YES
          继续讨论
```

- YES 连线：实线 + 末端箭头，向下
- NO 连线：红色虚线 + 红色箭头，向右
- 共 11 个节点（5 主 + 5 右侧支路 + 1 底部终点），仅主节点可点击

### 4.2 交互

| 操作 | 效果 |
|------|------|
| 点击主节点 | 该节点高亮（橙色底 + 橙色描边），其 NO 支路变亮加粗，右侧面板同步 |
| 面板内容 | 序号 + 问题 → `q` → 说明 → YES 分支（绿）→ NO 分支（红）→ 两个跳转按钮 |
| 首次滚动到视口 | 所有连线按索引 × 55ms 依次 draw-in（420ms），标签延迟 260ms 淡入 |

### 4.3 降级

若 `window.d3` 不存在：隐藏 SVG，显示提示文本，但仍渲染第 1 个节点的说明面板——保证信息不丢失。

## 五、精度等级 `#precision`

**状态**：`level: 0..6`，默认 1（一般交流）

| 操作 | 效果 |
|------|------|
| 拖动滑块 | 触发下方全部更新 |
| 点击刻度文字 | 直接跳到该档位 |
| 键盘 ← → | 原生 range 行为，同样触发更新 |

**一次 `apply(level)` 会同步 6 处：**

| 位置 | 变化 |
|------|------|
| 档位名 + 序号 | 「一般交流」/ `Lv.2 / 7 · 讨论成本 低` |
| 滑块填充 | `--fill` 百分比 |
| 四行星级 | 概念 / 标准 / 事实 / 逻辑 的星级与 `n/5` |
| 误差容忍条 | 宽度 + 百分比数值（红 → 橙 → 绿渐变） |
| 右侧四条要求说明 | 每条基线在当前档位下的具体要求 |
| **跨模块** | 五大基线卡片底部星级 + 导航徽标文字 |

同时在 `<html>` 上写入 `data-precision`，供未来扩展做样式联动。

## 六、讨论诊断器 `#analyzer`

### 6.1 输入

- 文本框：粘贴讨论内容
- 实时显示字数统计
- `Ctrl/Cmd + Enter` 快捷分析
- 「填入示例」按钮写入预置的低质量讨论样本

### 6.2 分析流程

```
点击「分析」
  → 输出区加 .is-busy（扫光动画）
  → 延时 260ms
  → 五个维度并行跑规则引擎
  → 渲染：结论徽标 → 五维评分条 → 命中信号列表
  → 移除 .is-busy
```

260ms 延时是为了让扫光动效可见，同时避免大段文本时的卡顿感。

### 6.3 输出

| 区块 | 内容 |
|------|------|
| 结论徽标 | 「继续讨论」/「修复后再谈」/「先补基础」/「退出讨论」+ 一句话说明，颜色对应评级 |
| 五维评分条 | 每条 = 维度名 + 进度条（基线色）+ 分值 + 一句话诊断 |
| 命中信号 | 最多 12 条，按「维度 + 风险/支撑 + 命中词」列出，供用户核对 |

**设计原则：透明优先于聪明。** 所有命中词原样展示，用户能立刻看出是否误判。

### 6.4 雷达同步

分析完成后，输入区下方的雷达图同步显示五维得分。

## 七、讨论雷达 `#radar`

**状态**：`{ concept, standard, evidence, logic, gain }`，各 0–5

| 操作 | 效果 |
|------|------|
| 拖动任一滑块 | 雷达多边形实时形变（0.45s 过渡），下方建议文字更新 |
| 点击预设按钮 | 一次性载入 5 个维度的值 |

**预设**：理想讨论 / 学术讨论 / 工作决策 / 日常闲聊 / 网络争论

**建议文字生成逻辑**：

```
avg = 五维均值
avg ≥ 4.4         → 高质量，保持
avg ≤ 1.6         → 全面塌陷，先补概念与标准
其他              → 取最低维度，给出该维度的针对性建议
```

## 八、案例分析 `#cases`

**状态**：`current: 0..4`，默认 0（直播带货）

| 操作 | 效果 |
|------|------|
| 切换 Tab | 重渲染整个案例区 |
| 案例区内容 | 观点 A / 观点 B 双栏 → 五维星级 → 真正的分歧点 → 结论 → 三个联动按钮 |

**三个跨模块联动按钮：**

| 按钮 | 行为 |
|------|------|
| 在雷达图中查看 | 把案例五维得分灌入雷达模块，并平滑滚动到 `#radar` |
| 用诊断器分析 | 把案例文本写入诊断器输入框并立即分析，滚动到 `#analyzer` |
| 带入自检清单 | 按案例实际情况预勾选自检项，滚动到 `#checklist` |

> 案例的预设勾选只勾选"该案例确实做到了"的项。
> 例如 NBA GOAT 案例勾选「概念一致」「事实可靠」，而不勾「标准一致」——
> 正是为了凸显分歧出在标准层。

## 九、认知增量 `#gain`

静态展示，无状态：

- 大标题「讨论最大的价值，不一定是得到答案，而是增加认知」
- 7 段演化链：讨论 → 新事实 → 新定义 → 新标准 → 新逻辑 → 问题缩小 → 认知增加
  （段间箭头使用 `assets/svg/flow-arrow.svg` 配 CSS mask，可跟随主题变色）
- 6 条「什么算认知增量」
- 金句区：**高质量讨论未必产生共识，但一定产生认知增量**

## 十、退出讨论判断 `#exit`

### 10.1 状态机

```
picks = [null, null, null]   // null = 未答，true = YES，false = NO
```

**激活规则**：第 i 题处于激活态，当且仅当它之前的所有题都已答且全为 NO。

**点击规则**：

```
点击第 i 题的 YES/NO
  → picks[i] = 与上次相同 ? null : 值      // 再点一次可取消
  → picks[i+1..] 全部清空为 null           // 改上游答案会作废下游
  → 重绘
```

### 10.2 视觉状态

| 状态 | 样式 |
|------|------|
| 未激活（上游未走完） | `.is-off` 透明度 .34 |
| 激活且已答 YES | `.is-on` 橙色底 + 橙色描边 |
| 激活且已答 NO（最后一题） | `.is-last` 红色底 + 红色描边 |
| 选中的按钮 | YES 绿 / NO 红，对应 `.is-on` |

### 10.3 结论区

| `picks` | 结论 |
|---------|------|
| `[null,…]` | 待判断 —— 从 Q1 开始 |
| `[true,…]` | **继续讨论** —— 还有新事实可能出现 |
| `[false,true,…]` | **继续讨论** —— 概念还能统一 |
| `[false,false,true]` | **继续讨论** —— 标准还能协商 |
| `[false,false,false]` | **停止讨论** —— 边际收益接近零 |
| 中间态 | 回答中 —— 提示继续回答第几题 |

**底部公式**：`退出讨论 = 认输`（划掉）`≠` `退出讨论 = 没有新的认知增量`

## 十二、自检清单 `#checklist`

**状态**：`state: boolean[6]`，初始全 false

| 操作 | 效果 |
|------|------|
| 点击任一项 | 切换勾选；绿色底 + 绿色描边，复选框填充并打勾 |
| 评分变化 | 数字 rAF 缓动（easeOutCubic，480ms）；进度环 `stroke-dashoffset` 同步；评级与提示更新 |
| 「重置」 | 全部取消勾选，评分归零 |

**评级档位：**

| 勾选数 | 百分比 | 评级 | 环颜色 |
|-------|-------|------|--------|
| 0 | 0% | Not started · 尚未开始 | `--text-faint` |
| 1 | 17% | Fragile · 基础薄弱 | `--red` |
| 2 | 33% | Fragile · 基础薄弱 | `--red` |
| 3 | 50% | Fair · 尚需补齐 | `--accent` |
| 4 | 67% | Good · 基本合格 | `--accent` |
| 5 | 83% | Strong · 质量良好 | `--green` |
| 6 | 100% | Complete · 完整 | `--green` |

**提示文字**：显示当前评级说明；若未全勾，额外列出「待补齐：XXX、YYY」。

评分区在宽屏下 `position: sticky`，跟随滚动。

## 十三、思维原则 `#principles`

结尾屏，四句递进（中间用向下箭头连接）：

1. 高质量讨论的目标不是证明自己正确 —— **划掉**（`.is-x`）
2. 而是不断减少误解
3. 不断增加认知
4. 在无法增加认知时停止讨论 —— 最后一句用橙色强调底

## 附录：降级清单

| 条件 | 降级行为 |
|------|---------|
| `window.d3` 缺失 | 流程图隐藏并显示提示，面板仍渲染；雷达图不绘制，其余功能不受影响 |
| `IntersectionObserver` 缺失 | Reveal 元素直接显示，流程图连线立即绘制 |
| `prefers-reduced-motion` | 全部动效关闭，Hero 粒子不启动 |
| `localStorage` 不可用（隐私模式） | 主题不持久化，仅本次会话有效 |
| Canvas 不可用 | Hero 无粒子背景，渐变光晕与网格遮罩仍在 |
