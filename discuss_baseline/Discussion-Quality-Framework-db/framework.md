# 框架本体 · The Framework

> 本文件是 Discussion Quality Framework 的**内容权威**：五大基线、流程、宽容度、认知增量、退出决策、自检清单的完整定义。
> 页面展示内容以此为唯一来源，如需修改内容请先更新本文件。

## 0. 核心主张

**讨论的目标不是"说服"，而是"理解"。**
把讨论从"输赢"转向"认知"—— 一次高质量讨论未必产生共识，但**一定产生认知增量**。

## 1. 五大基线

一次讨论，检查五个维度：

### 01 · 概念定义（Concept）

- **本质**：确定讨论对象。
- **为什么重要**：很多争论不是观点不同，而是讨论的对象不同。没有统一定义，后面所有推理都建立在不同对象上。
- **常见错误**：偷换概念、语义混乱、对象不同步。
- **示例**："AI 会取代程序员"—— AI 指什么（LLM / Agent / AGI）？取代是什么意思（全部失业 / 岗位减少 / 方式改变）？程序员范围（初级 / 高级 / 全部）？
- **何时严格**：学术讨论必须精确定义，必要时给出操作性定义；日常讨论可允许模糊。

### 02 · 标准约束（Standard）

- **本质**：确定评价函数 —— 什么算"成立 / 对 / 好"。
- **为什么重要**：标准不同时双方都可能正确——不是事实冲突，而是评价体系不同。没有评价函数，就不存在统一结论。
- **常见错误**：评价体系不同、标准隐含、权重不明。
- **示例**："世界第一"可用收入、奖项、技术水平、商业价值或历史影响力衡量。
- **何时严格**：学术讨论必须说明评价指标、权重与理由；日常讨论允许隐含标准。

### 03 · 事实依据（Evidence）

- **本质**：保证前提真实。
- **为什么重要**：即使定义、标准、逻辑都对，事实错了结论依然会错。逻辑只保证"前提为真则结论成立"，不能保证前提本身真实。
- **常见错误**：假数据、证据不足、来源不可靠。
- **示例**："中国 GDP 增长"不等于"每个人都更富有"；需区分数据、样本、来源、偏差与统计方法。
- **何时严格**：学术讨论要求可验证、可复现、可溯源；日常讨论可接受个人经历与常识。

### 04 · 逻辑遵循（Logic）

- **本质**：保证推理有效。
- **为什么重要**：中间每一步都需要证明：不跳步、不偷换、不循环论证、不把相关当因果。
- **常见错误**：跳步、偷换概念、循环论证、相关当因果。
- **示例**：GDP 增长 → 收入增长 → 所有居民更富有？每一步都需要证明。
- **何时严格**：学术讨论必须完整严谨；日常讨论允许部分跳步和直觉推理。

### 05 · 认知增量（Cognitive Gain）

- **本质**：评估讨论收益。
- **为什么重要**：把讨论目标从"改变他人"转变为"增加认知"。讨论最大的价值不一定是得到答案，而是缩小问题。
- **常见错误**：以输赢为目标、只重复观点、无信息增量。
- **示例**：讨论后变成"我们真正分歧的是'效率优先'还是'就业优先'"——问题被缩小了，这就是认知增量。
- **验收**：高质量讨论结束时，双方都能准确表述——自己的观点、对方的观点、真正分歧在哪里、为什么目前无法统一。

## 2. 讨论流程（Flow）

```
开始
  → 概念一致？  NO → 退出讨论
  → 标准一致？  NO → 退出讨论
  → 事实一致？  NO → 退出讨论
  → 逻辑成立？  NO → 退出讨论
  → 产生认知？  NO → 退出讨论
  → ✓ 继续讨论
```

五道关卡，任一失败即退出；全部通过则继续。

## 3. 讨论宽容度（Precision Slider）

不同场景对四要素的严格程度不同：

| 场景 | 概念 | 标准 | 事实 | 逻辑 | 容忍误差 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 闲聊 | 可模糊 | 可隐含 | 接受常识 | 允许跳步 | 极大 |
| 工作讨论 | 需明确 | 需明确 | 需较可靠 | 需较完整 | 较大 |
| 技术讨论 | 需精确定义 | 需显式标准 | 需可验证 | 需严谨 | 中等 |
| 科研论文 | 必须操作性定义 | 必须说明指标权重 | 必须可复现可溯源 | 严谨完整 | 小 |
| 数学证明 | 必须操作性定义 | 必须说明指标权重 | 必须可复现可溯源 | 几乎零容忍 | 极小 |

**核心规则**：讨论越接近"数学证明"，对四要素的要求越高、容忍误差越小。先用宽容度对齐场景，再决定严格程度。

## 4. 认知增量

- **信息增量**：获得新的、可验证的事实或数据。
- **理解增量**：更准确地理解对方观点及其依据。
- **问题增量**：真正的问题被缩小、被更清晰地表述。

讨论最大的价值不一定是得到答案，而是**缩小问题**。

## 5. 是否退出讨论（Exit Decision Tree）

逐题回答：

1. 双方对象一致吗？（概念定义是否已对齐）
2. 标准一致吗？（评价函数是否已对齐）
3. 事实可靠吗？（关键事实是否可验证）
4. 逻辑成立吗？（推理是否有效、无跳步）
5. 还能产生认知吗？（继续是否有边际收益）

任一答案为 **NO**，说明继续讨论的边际收益接近零 —— **退出 ≠ 认输，而是理性的认知决策**。

## 6. 讨论质量自检清单（Checklist）

1. 明确讨论对象 —— 双方清楚"我们在讨论什么"吗？
2. 定义关键概念 —— 关键术语是否已统一定义？
3. 明确评价标准 —— 判断对错 / 好坏的标准是否清楚？
4. 核实事实依据 —— 所依赖的事实是否可靠、可验证？
5. 检查逻辑链条 —— 推理是否连贯，有无跳步或偷换？
6. 评估认知增量 —— 讨论是否产生了新的认知？

**评分口径**：0–2 有待提升（LOW）；3–4 中等（FAIR）；5 良好（GOOD）；6 优秀（EXCELLENT）。

## 7. 讨论分析器规则（Analyzer）

对输入文本按五个维度打分（1–5 ★）：

| 维度 | 高分信号 | 低分信号 |
| ---- | ---- | ---- |
| 概念 | 出现定义词（是指 / 定义为 / 特指…） | 模糊词（公平 / 自由 / 应该…）、绝对化（都是 / 一定…） |
| 标准 | 出现准则词（标准 / 指标 / 权重…） | 隐式价值词（骗 / 割韭菜 / 垃圾…）、观点词（我觉得…） |
| 事实 | 出现证据词（数据 / 报告 / 研究…） | 无证据的强断言（都是 / 肯定…） |
| 逻辑 | 出现推理词（因为 / 所以 / 意味着…） | 绝对化断言 |
| 认知 | 开放式 / 疑问式表达（是否 / 为什么 / 可能…） | 封闭式断言、无问题意识 |

> 说明：当前为实现为零依赖的**规则启发式**。替换为 LLM 接口时，仅需重写 `analyzer.js` 中 `analyze()` 的返回结构（`{ dims, advice, verdict }`），页面其余部分无需改动。
